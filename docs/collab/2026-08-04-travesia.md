# La Travesía del Estero — two-agent work split (2026-08-04)

## Context

Stage **s8, "La Travesía del Estero"**, is being rebuilt. What ships today is a
rail-guided boat ride: the player holds a tiller while the boat follows a fixed
route, and the stage is really a timing exercise on somebody else's line. What
replaces it is a **gated obstacle race** — a genuinely drivable water vehicle
crossing the estero through a sequence of gates, with boyas, pangas and the
current between the player and the far bank. On the world side the **Muelle de
Pitahaya** is being aligned with the **Muelle Nacional** at the estero end of
Calle Central, so the two ends of the crossing are real quays that face each
other instead of a berth and a bare landing ramp. Two agents work this in
parallel — Codex owns the world and everything generated from it, Claude owns
the running game — and the seam between them is the emitted manifest.

## The data seam

Two manifest arrays are the whole contract. Codex produces them in
`churchill/world/`; they arrive in `src/world2d/manifest.json`; Claude's game
code reads them **by id, read-only, and never writes them**.

- **`manifest.ferries[]`** — the crossing itself. Fields the game reads:
  `route` (flat world-px polyline), `berth` (world-px start), `deck`
  (`[length, beam]` in px), `dockS` (dock radius), `speed`, `oneWay`.
  The Travesía uses the `pitahaya` entry.
- **`manifest.piers[]`** — the quays. Existing entries stay as they are; this
  work adds the new **`muelle_pitahaya`** entry, aligned with
  `muelle_nacional`.

Rules that keep the seam honest:

- Claude's code looks entries up by `id` (`"pitahaya"`, `"muelle_pitahaya"`,
  `"muelle_nacional"`), never by array index — the order is a build detail.
- A field the game needs that does not exist yet is a **request to Codex**, not
  a local patch to `src/world2d/`. That directory is generated; hand-edits are
  overwritten by the next `pnpm world:build` and break
  `python3 tools/world_snapshot.py verify`.
- A world change that alters the emitted bytes re-runs
  `python3 tools/world_snapshot.py save` in the same commit.

## A note on `inventory.json`

Both sides' conventions regenerate it — Codex after a world rebuild, Claude
after a module change — so it will conflict on nearly every merge. **Do not
merge `inventory.json` by hand.** Whoever lands second takes the incoming
version and re-runs `pnpm inventory`. Same for `docs/lotes_catalog.json` after a
world rebuild (`python3 tools/gen_lotes.py`).
